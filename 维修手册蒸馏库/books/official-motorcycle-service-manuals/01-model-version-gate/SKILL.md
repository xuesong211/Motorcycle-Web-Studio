# 车型—版本—实车三点适用性门禁

## R — 原文

> “由于产品的不断改进提高，以及其它方面的改变，因此您的摩托车可能与本手册存在某些不一致的地方。”
>
> — 升仕《703F_2024与2026维修手册》，PDF第2页

## I — 方法论骨架

维修数据不是只跟“商品名”绑定，而是跟制造身份和技术版本绑定。
先确认实车是谁，再确认手册写的是谁，最后逐项核对会影响维修结论的实物差异。
身份核对至少包含 VIN/工厂型号、发动机型号、年款或排放版、关键零件号。
实物核对至少包含插接器针数、传感器位置、紧固件规格和控制器标识。
三点一致，手册中的扭矩、标准值、针脚与流程才可直接使用。
存在差异时先找补充页、更新版或品牌技术通报，不把相似车型数据当成事实。

## A1 — 手册中的应用

### 案例：703F版本差异提示
- **问题**：同为703F，不同改进批次的实车可能和手册图示不同。
- **使用**：手册先声明其编制基准，并要求对实车差异保持警惕。
- **结论**：型号名称相同不能自动证明零件、线路和数据完全相同。
- **结果**：技师应先完成版本映射，再进行拆装和测量。

### 案例：ATR125识别资料
- **问题**：维修数据需要对应到具体车辆。
- **使用**：手册在进入系统维修前提供车型/识别信息位置。
- **结论**：识别码是检索正确资料的入口，不是接车记录中的装饰字段。
- **结果**：后续诊断与订件能够绑定到可追溯实车。

## A2 — 触发场景

1. 手册插图、针脚或零件位置与实车不一致。
2. 需要跨年款、跨排放版或跨同平台车型借用维修数据。
3. 订件、刷写控制器、测线路或执行关键扭矩前身份不完整。
4. 用户只提供“灰石、368、703、450 Rally”等商品名。

语言信号：`同排量能不能通用`、`manual mismatch`、`插头对不上`、`这是哪一版`、`零件号不同`。

与相邻能力的最终区分：本能力只判断“资料是否有资格使用”；具体报码走 `motorcycle-dtc-evidence-loop`，具体测量走 `motorcycle-measurement-decision-engine`。

## E — 可执行步骤

1. **建立实车身份卡**：记录 VIN、工厂型号、发动机型号/号、年款/排放版、里程和铭牌照片。
   - 完成标准：每一项有可复核文字或照片，不接受“应该是”。
2. **建立资料身份卡**：记录手册全名、发布日期/版本、适用车型和来源文件哈希。
   - 完成标准：能从 `SOURCE_CATALOG.md` 回到原 PDF。
3. **比较高风险差异**：核对控制器/零件号、插头、传感器、紧固件和关键数值。
   - 判停条件：任一关键差异无法解释，停止通电、拆装和订件。
4. **作出资料资格结论**：标记“直接适用 / 仅作结构参考 / 禁止用于数值与针脚”。
   - 完成标准：工单写明结论、依据和待补资料。

## B — 边界

- 不要用商品名、外观或排量相近代替身份核对。
- 不要用未经确认的近似车型扭矩、ECU针脚或维修极限。
- 资料已确认且实车无差异时，不要反复调用本能力拖慢常规工序。
- 本合集为公开资料快照；实修前仍需检查品牌最新技术通报与零件系统。

失败模式：拿旧年款数据直接套新车；发现插头不同仍按图供电；用“同平台”推定零件可互换。
